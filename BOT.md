# Telegram-бот — налаштування та автостарт

Той самий рушій (`abit_parser.engine`), що й CLI/GUI, у вигляді приватного Telegram-бота на домашньому хостингу. Long-polling — не треба білого IP, прокидання портів чи SSL.

## Встановлення

```bash
pip install "python-telegram-bot==22.8" python-dotenv
```

## Налаштування

1. Токен від [@BotFather](https://t.me/BotFather) (команда `/newbot`).
2. Скопіюй `.env.example` → `.env` і встав туди токен:
   ```
   TELEGRAM_ABIT_BOT_TOKEN=твій-токен
   ```
3. **`.env` у `.gitignore` — ніколи не комітиться.** Токен ніде більше в коді не хардкодиться.

### Опційно — спільний код доступу

За замовчуванням бот відкритий для всіх, хто знає хендл (приватність через необізнаність). Якщо хочеш страховку на випадок витоку хендла — розкоментуй у `.env`:

```
TELEGRAM_ABIT_ACCESS_CODE=якийсь-код
```

Один код на всіх, перевіряється один раз при `/start` (тримається в пам'яті процесу — після рестарту бота треба ввести код ще раз).

## Запуск

```bash
python bot.py
```

Кеш пошуку по імені і так уже лежить у `%APPDATA%\parser-abit\cache\search\` — спільний для CLI/GUI/бота, переживає рестарти.

## Автостарт на домашній машині (Windows)

Процес має жити постійно й підніматись сам після ребута/краху. Два варіанти:

### Варіант A — NSSM (простіше, рекомендовано)

На цій машині NSSM вже лежить у `C:\nssm-2.24\win64\nssm.exe`, а служба `AbitBot` уже створена. Все нижче — команди від адміністратора (правий клік на PowerShell → «Запуск від імені адміністратора»); `nssm set`/`nssm start` без підвищення falls з `Access is denied`.

**З нуля:**
```powershell
& "C:\nssm-2.24\win64\nssm.exe" install AbitBot "C:\Users\Trener\miniconda3\python.exe" "bot.py"
& "C:\nssm-2.24\win64\nssm.exe" set AbitBot AppDirectory "C:\Parser\parser-abit"
& "C:\nssm-2.24\win64\nssm.exe" set AbitBot Start SERVICE_AUTO_START
& "C:\nssm-2.24\win64\nssm.exe" set AbitBot AppExit Default Restart
& "C:\nssm-2.24\win64\nssm.exe" start AbitBot
```

- **`Start SERVICE_AUTO_START`** — служба піднімається сама разом з Windows, ще до входу в акаунт. Це і є «поки увімкнений пристрій — бот увімкнений».
- **`AppExit Default Restart`** — при будь-якому завершенні процесу (краш, виняток) NSSM перезапускає його сам.

**Керування:**
```powershell
nssm stop AbitBot      # тимчасово вимкнути
nssm start AbitBot      # увімкнути назад
nssm restart AbitBot    # перечитати .env/код після зміни файлів
sc query AbitBot        # поточний стан (RUNNING/STOPPED/PAUSED) — без адмінправ
```

Логи: `nssm set AbitBot AppStdout "C:\Parser\parser-abit\service.log"` і `AppStderr` так само — інакше вивід нікуди не пишеться.

> **Граблі, на які легко наступити:** на машині може бути кілька `python.exe` одразу (Miniconda, Windows Store, звичайний інсталятор) — `where python` показує ВСІ, перший у списку не обов'язково той, куди ставились залежності бота. Служба, запущена не тим інтерпретатором, падає на `ModuleNotFoundError: No module named 'telegram'` при старті, NSSM після кількох невдалих рестартів переводить її в `SERVICE_PAUSED` (перевірити: `sc query AbitBot` — це вже саме так і сталось один раз). Перевірити правильний інтерпретатор: `python -c "import telegram; print(telegram.__file__)"` — якщо видає шлях, а не `ModuleNotFoundError`, це той самий `python.exe`, який треба вказати в `Application`.
>
> **Не запускай одночасно `python bot.py` вручну й службу** — обидва тримають той самий токен, Telegram дозволяє лише одного активного поллера, другий отримає `Conflict: terminated by other getUpdates request`.

### Варіант B — Task Scheduler (без сторонніх утиліт)

1. Відкрий Планувальник завдань → **Create Task** (не Basic Task — потрібні розширені опції).
2. **General:** ім'я `AbitBot`, "Run whether user is logged on or not", "Run with highest privileges".
3. **Triggers → New:** "At startup" (автостарт після ребута).
4. **Actions → New:**
   - Program/script: шлях до `python.exe`
   - Add arguments: `bot.py`
   - Start in: `C:\Parser\parser-abit`
5. **Settings:** увімкни "If the task fails, restart every: 1 minute", "Attempt to restart up to: 999 times" (максимум у діалозі — цього достатньо для практичного "завжди перезапускати").
6. OK → введи пароль користувача, від імені якого запускається завдання.

Task Scheduler не вміє "рестарт при краші процесу" так само зручно, як NSSM (тільки "якщо ЗАВДАННЯ (не сам процес) завершилось з помилкою") — якщо бот падає без ненульового exit-коду, це може не спрацювати. NSSM надійніший саме для "тримати процес живим".

## Що вже враховано в коді (не треба додатково)

- **Глобальний тротлінг** (`abit_parser/throttle.py`) — усі запити на abit-poisk.org.ua серіалізовані по всьому процесу з паузою 1-3с, незалежно від того, скільки юзерів аналізують одночасно.
- **Спільний персистентний кеш** пошуку з TTL (`CACHE_TTL_HOURS` у `abit_parser/config.py`, дефолт 12 год) — другий юзер на ту саму спеціальність не б'є сайт вдруге, але й дані не висять протухлими вічно.
- **`concurrent_updates=True`** — аналіз одного юзера (може йти до ~2 хв) не блокує повідомлення інших.
- **Один активний аналіз на юзера** — повторний запуск, поки перший рахується, ігнорується з поясненням.

## Стеження («🔔 Стежити»)

Після результату — кнопка, яка підписує чат на періодичну автоперевірку того самого запиту. Реалізація:

- Підписки — `%APPDATA%\parser-abit\bot_subscriptions.json` (`bot_storage.py`), переживають рестарт служби: при старті бот перечитує файл і перереєстровує джоби (джоби `JobQueue` живуть тільки в пам'яті процесу).
- Час перевірки — по системному годиннику машини (`JobQueue.run_daily`), **не** "раз на N годин від старту процесу" — інакше графік плив би після кожного авторестарту.
- Кожен чат отримує **свій, стабільний, але різний** час (похідний від `chat_id`, дві перевірки на добу рівно через 12 год) — щоб кілька підписників не били сайт одним залпом запитів в один момент.
- Порівнюється знімок (вердикт + межі + очікувана, округлена до 0.1) з попереднім; якщо однаково — жарт зі списку `track.jokes.nothing_changed` у [texts.toml](texts.toml), якщо ні — повний оновлений результат.
- `/untrack` знімає підписку і скасовує заплановані джоби.

## Аналіз по всіх пріоритетах ("📚 Порахувати по всіх пріоритетах")

Кнопка на результаті одиночного аналізу — не змінює основний флоу, чисто опційне продовження. Дозволяє докинути ще заявки (URL + бал + пріоритет + бюджет/контракт кожна, до 9 штук — стільки, скільки максимум буває пріоритетів), і на завершення показує їх усі разом, відсортовані за зростанням пріоритету, плюс один висновок: перший пріоритет у списку, де вердикт впевнено "проходиш" (`engine.run_priority_chain`, `bot.py` — `chain_start`/`chain_ask_*`/`chain_run`). Жодної нової математики — просто послідовний прогін уже наявного `run_analysis()` по кожній заявці.

Свідоме спрощення: кожна заявка рахується незалежно, без моделювання того, як вони одночасно впливають одна на одну (та сама методологічна межа, що вже описана в README). Контракт і "🔔 Стежити" для ланцюжка поки не підтримані — тільки бюджет, тільки одноразовий розрахунок.

## Тексти бота (texts.toml)

Усі слова, якими бот спілкується — привітання, підказки, статуси, жарти, підписи кнопок, `/help` — лежать окремо від коду, у [texts.toml](texts.toml), і підвантажуються автоматично при старті (`bot_texts.py`). Це звичайний текстовий файл — можна відкрити і переписати що завгодно, включно з жартами зі стеження, без торкання `bot.py`. Формат і що можна/не можна чіпати — пояснено коментарями на початку самого файлу.
